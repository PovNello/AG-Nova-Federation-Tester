OpenID Connect (OIDC)

Token-based identity flows built on top of OAuth 2.0

🔒
Auth Code + PKCE
Authorization Code flow with Proof Key for Code Exchange. No client secret needed — designed for public clients.
🌐 Browser only
🗝️
Auth Code + Secret
Authorization Code flow with a confidential client secret. Token exchange proxied through backend.
⚙️ Backend-assisted
🤖
Client Credentials
Machine-to-machine grant. No user involved — the client authenticates directly for an access token.
⚙️ Backend-assisted
📄

SAML 2.0

XML-based federation — see the raw AuthnRequest and decoded SAMLResponse assertion

⚠️ SAML flows require a publicly reachable ACS URL. Deploy to Vercel first — they will not work on localhost.
➡️
SP-Initiated SSO
The Service Provider generates an AuthnRequest and redirects the user to the IdP to authenticate.
📄 SAML 2.0
⬅️
IdP-Initiated SSO
The Identity Provider initiates the session and POSTs a SAMLResponse directly to the ACS endpoint.
📄 SAML 2.0
