SCIM 2.0 Server

Provisioning is push: the identity provider (Entra ID) calls your SCIM endpoint to create, update and delete users and groups. This page is that endpoint — and shows you every call it receives.

⚠️ In-memory storage. No Redis configured: data is lost when the server restarts, and on Vercel it may vanish between requests. Set KV_REST_API_URL / KV_REST_API_TOKEN (Upstash) for reliable storage.
🌐 You are on localhost. Entra ID cannot reach it — use the deployed site or a public tunnel (e.g. ngrok). You can still test with the curl example below.
0
How it works

Entra ID → GET /Users?filter=userName eq "…" (does the user exist?) → POST /Users (create) → PATCH /Users/{id} (changes) → DELETE /Users/{id} (deprovision). Groups work the same way via /Groups and members operations.

Requests are authenticated with a bearer Secret Token. Data is kept per endpoint for 7 days and only the last 200 requests are logged. Passwords sent by the IdP are masked in the log and never stored.

2
Connect Entra ID
  1. Entra admin center → Enterprise applications → New application → Create your own application (non-gallery).
  2. Open it → Provisioning → Get started → Provisioning Mode: Automatic.
  3. Admin Credentials: paste the Tenant URL and Secret Token above → Test Connection. You should see a GET /Users?filter=… in the log below.
  4. Mappings: review the user / group attribute mappings.
  5. Users and groups: assign users / groups to the app.
  6. Provision on demand pushes one user right away; Start provisioning runs the cycle (about every 40 minutes).
