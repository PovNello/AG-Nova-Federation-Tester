## 🚀 Project Overview
An educational, provider-agnostic tester for **SAML 2.0** and **OIDC** federation flows. 
Unlike standard client libraries, it **does not hide** intermediate steps or raw payloads. It exposes exact HTTP requests/responses, deflated XML, and decoded JWTs for learning and debugging purposes.

## 🛠️ Key Features & Logic

### OIDC Implementation
- **PKCE Generation**: Native Web Crypto API used in `shared.js` to create `code_verifier` and `code_challenge` (S256).
- **Token Decryption**: Custom JWT decoder in `shared.js` splits tokens into Header/Payload/Signature without external libs.
- **Token Truncation**: Long tokens are truncated in UI for readability but remain copyable in full.
- **Parameter Extensibility**: Supports adding arbitrary URI parameters (e.g., `prompt`) via dynamic tables.
- **Device Flow Polling**: Real-time polling with "Slow Down" and "Pending" state handling.

### SAML 2.0 Implementation
- **AuthnRequest**: Generated by the backend (`/api/saml-request`) using `zlib` for DEFLATE compression.
- **ACS Endpoint**: Reusable endpoint (`/saml/acs`) that accepts IdP POST responses, parses the XML, and displays the result visually.
- **Metadata Generation**: Dynamic SP metadata available at `/saml/metadata`.

### UI/UX Standards
- **Step-by-Step Flow**: Each flow is broken into "Step Cards" starting from **Step 0**.
- **Terminal View**: Requests are rendered in a terminal-style block showing Method, URL, and Body.
- **Auto-Save**: Form inputs are persisted in `sessionStorage` via `attachAutoSave` in `shared.js`.
- **Auto-Scroll**: The page automatically scrolls to new results (e.g., after receiving a code or token).
